## 🚀 **v8.5.0 - 最新版（2025年10月14日）**

### 🆕 **パフォーマンス最適化と分類精度改善（v8.5.0）**

#### 🎯 **実装内容**

**1. PDFテキスト抽出の最適化**
- ✅ **1ページ目のみ処理**: 全ページスキャンから1ページ目のみに変更
- ✅ **処理速度向上**: 大幅なパフォーマンス改善
- ✅ **3箇所最適化**:
  - `_process_regular_pdf_v5()` - 通常PDFの処理
  - `_process_pdf_file_v5_with_snapshot()` - スナップショット処理
  - `_should_split_file()` - 分割判定処理
- ✅ **分類精度維持**: 1ページ目に必要な分類情報が含まれている

**2. 分類ロジックの改善**
- ✅ **0002ファイル名判定削除**: ファイル名に"法人税"がある場合の誤判定を解消
- ✅ **コンテンツベース分類**: ファイル名ではなくPDF内容で判定

#### 📊 **最適化詳細**

**変更前（v8.4.0）:**
```python
# 全ページを処理（遅い）
for page in doc:
    text += page.get_text()
```

**変更後（v8.5.0）:**
```python
# 1ページ目のみ処理（高速）
if len(doc) > 0:
    text = doc[0].get_text()  # 1ページ目のみ
```

#### 📈 **改善結果**

| 項目 | v8.4.0 | v8.5.0 | 改善点 |
|------|--------|--------|--------|
| **処理速度** | 全ページスキャン | 1ページ目のみ | 大幅に高速化 |
| **分類精度** | 高精度 | 高精度維持 | 1ページ目で十分 |
| **0002分類** | ファイル名でも判定 | コンテンツのみ判定 | 誤判定削減 |
| **大容量PDF** | 遅い | 高速 | ページ数の影響なし |

## 🚀 **v8.3.0 - 予定申告モード実装（2025年10月10日）**

### 🆕 **予定申告モードの実装（v8.3.0）**

#### 🎯 **実装内容**

**1. 処理プロセス選択機能**
- ✅ **処理モード選択**: UI上で「確定申告」または「予定申告」を選択可能
- ✅ **動的エンジン作成**: 選択されたモードに応じて分類エンジンとリネームエンジンを動的に生成
- ✅ **モード別ルール**: 各モードに最適化された分類ルールを適用

**2. 予定申告専用分類ルール**
- ✅ **法人税等申告書（予定申告）**: 優先度250で確定申告より優先
  - AND条件: 「法人税」+ 「予定申告書」+ 「納付すべき法人税額/地方法人税額」
- ✅ **消費税等申告書（予定申告）**: 優先度250で確定申告より優先
  - AND条件: 「中間申告書」+ 「消費税及び地方消費税」
- ✅ コードオーバーライド: 予定申告でも `0001_法人税等申告書` や `3001_消費税等申告書` のコードを使用

**3. UI改善**
- ✅ **Comboboxスタイル設定**: 白背景で読みやすいデザイン
- ✅ **フォーカス管理**: 選択後に自動的にフォーカスを外してクリーンな表示
- ✅ **ツールチップ**: 処理モードの説明を追加

**4. 分類エンジンの拡張**
- ✅ **process_modeパラメータ**: 分類エンジン初期化時にモードを指定
- ✅ **モードフィルタリング**: ルールに設定された `process_mode` と一致する場合のみ適用
- ✅ **後方互換性**: 既存のルール（確定申告）はデフォルトで適用

#### 📊 **処理フロー詳細**

**予定申告モード:**
```
1. UIで「予定申告」を選択
2. リネーム実行時に process_mode="予定申告" でエンジンを作成
3. 分類エンジンが予定申告専用ルールを優先適用
   - 「法人税」+ 「予定申告書」+ 「納付すべき法人税額」→ 0001_法人税等申告書
   - 「中間申告書」+ 「消費税及び地方消費税」→ 3001_消費税等申告書
4. ファイル名に適切なコードを付与してリネーム
```

**確定申告モード（従来通り）:**
```
1. UIで「確定申告」を選択（デフォルト）
2. リネーム実行時に process_mode="確定申告" でエンジンを作成
3. 分類エンジンが確定申告専用ルールを適用
   - 従来の分類ロジックを使用
4. ファイル名に適切なコードを付与してリネーム
```

#### 🔧 **技術実装**

**新規・修正メソッド:**
- `DocumentClassifierV5.__init__(process_mode)`: モードパラメータを追加
- `DocumentClassifierV5._check_highest_priority_conditions()`: モードフィルタリングロジックを追加
- `create_rename_engine(process_mode)`: モードパラメータを追加
- `TaxDocumentRenamerV5._on_start_folder_batch_processing()`: UI選択値を取得してエンジンを動的作成

**UIコンポーネント:**
- `process_mode_var`: Combobox用の変数（StringVar）
- Comboboxスタイル設定: 白背景、黒文字、選択時の色設定
- ツールチップ: 処理モードの説明を表示

### 🆕 **受信通知処理の改善（v8.2.0）**

- ✅ **Step 1**: 会社名で候補を絞り込み
- ✅ **Step 2**: 候補が1つなら即マッチ
- ✅ **Step 3**: 候補が複数なら市区町村名/税務署名で絞り込み

**3. スペース完全除去**
- ✅ フォルダ名・ファイル名から全角・半角スペースを完全除去
- ✅ 会社名・税務署名から改行・空白を完全除去
- ✅ クリーンで統一された命名規則

#### 📊 **処理フロー詳細**

**償却資産申告書:**
```
1. 本表ファイル処理
   - テキスト抽出で受信通知判定 → スキップ
   - 本表ファイルのみ処理 → フォルダ作成
   - スペース除去: "2505_市原市役所_固定資産税（償却資産）全資産申告（電算処理分）_Ndiot株式会社"

2. 受信通知検出（テキスト抽出）
   - "01_受信通知.pdf" を検出
   - AND条件判定: 「申告受付完了通知」+ 「送信された申告データを受付けました」

3. 受信通知分割・抽出
   - 各ページから会社名と税務署名を抽出
   - 改行・空白を完全除去

4. 2段階マッチング
   - 会社名「株式会社SeasideLink」で候補絞り込み
   - 同一会社が複数 → 税務署名「東京都渋谷都税事務所」で絞り込み
   - マッチしたフォルダに受信通知を配置
```

**給与支払報告書:**
```
1. 本表ファイル処理（償却資産と同様）

2. 受信通知検出（テキスト抽出）

3. 2段階マッチング
   - 会社名で候補絞り込み
   - 同一会社が複数 → 市区町村名で絞り込み
   - マッチしたフォルダに受信通知を配置
```

#### 🔧 **技術実装**

**新規メソッド:**
- `_is_receipt_pdf()`: テキスト抽出によるAND条件判定
- `_extract_company_and_office_from_receipt()`: 会社名・税務署名抽出（改行・空白除去）
- `_match_depreciable_folder()`: 2段階マッチング（会社名→税務署名）
- `_process_payroll_report()`: 給与支払報告書の2段階マッチング対応

**修正メソッド:**
- `_process_main_files_for_special()`: スペース完全除去、テキスト抽出判定
- `_process_depreciable_assets()`: テキスト抽出判定に統一
